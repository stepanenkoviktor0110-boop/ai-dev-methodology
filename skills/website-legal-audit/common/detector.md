# Технический детектор сайта

Цель — собрать факты о сайте машинно, не спрашивая пользователя то, что видно в
коде и сети. Результат детектора кормит чеклист ветки (ru/eu/both).

## Инструменты по приоритету

1. **Playwright** (`browser_navigate` → `browser_network_requests`) — самый
   надёжный: видит реальные сторонние запросы после рендера (метрики, шрифты,
   пиксели подгружаются динамически и в статичном HTML их часто нет).
2. **WebFetch** — быстрый разбор HTML: ссылки на политику, cookie-баннер,
   реквизиты, формы. Дешевле Playwright, но не видит динамику.
3. **PowerShell `Resolve-DnsName`** + гео-IP — геолокация хостинга.

Порядок: WebFetch для статики → Playwright, если нужен список реальных сетевых
запросов → DNS для хостинга.

## Что детектить

### Сторонние сервисы (триггеры трансграничной передачи / запретов)

| Сигнал в коде/сети | Что значит | Норма |
|---|---|---|
| `google-analytics.com`, `googletagmanager.com`, `gtag(`, `ga(` | Google Analytics → трансграничная передача ПДн | RU: уведомление РКН или замена; EU: consent до загрузки |
| `connect.facebook.net`, `fbq(` | Meta Pixel → трансгранична + запрещённый ресурс | RU: blocker; EU: consent |
| `fonts.googleapis.com`, `fonts.gstatic.com` | Google Fonts с зарубежного CDN → трансграничная передача (IP уходит за рубеж) | RU: заменить на локальные шрифты |
| `mc.yandex.ru`, `metrika` | Яндекс.Метрика → РФ-сервис, ОК | — |
| виджеты WhatsApp/Facebook/Instagram-кнопки | реклама/связь через запрещённые ресурсы | RU: убрать/пометить |
| внешние чаты, карты, CDN (jsdelivr, unpkg, cloudflare) | проверить, не утекают ли ПДн/IP за рубеж | по ветке |

Сбор: `browser_network_requests` → выписать все домены, не совпадающие с
хостом сайта. Каждый внешний домен → классифицировать по таблице.

### Юридические артефакты на сайте

| Что ищем | Как | Сигнал «есть» |
|---|---|---|
| Политика обработки ПДн / Privacy Policy | поиск ссылок со словами `политик`, `конфиденциальн`, `privacy`, `/policy`, `/privacy` | ссылка ведёт на 200, текст по теме |
| Ссылка на политику под формами и в футере | разметка форм + футер | ссылка рядом с каждой формой сбора |
| Cookie-баннер | поиск `cookie`, `куки`, баннер/всплывашка | EU: должен быть opt-in с «Отклонить» |
| Согласие (галочка у формы) | `input[type=checkbox]` у форм + текст рядом | непредзаполненная галочка, отдельные цели |
| Реквизиты продавца | поиск `ОГРН`, `ОГРНИП`, `ИНН`, наименование, адрес | для интернет-магазина обязательно |
| Публичная оферта | ссылка `оферта`, `условия`, `terms` | страница есть |
| Формы сбора ПДн | `<form>`, `input` name/email/tel | определяет, нужен ли вообще блок ПДн |
| Достоверность реквизитов оператора | заявленное юрлицо (ООО/LLC/ИП) сверить с фактическим статусом | несуществующее юрлицо на сайте = находка (недостоверные реквизиты) |

### Хостинг и локализация

```powershell
Resolve-DnsName <domain> -Type A   # получить IP
```
IP → гео-проверка (ipinfo.io/<ip>/country через WebFetch). Страна не RU при
российской аудитории → флаг по локализации (RU-ветка, ч.5 ст.18). Учитывай
CDN (Cloudflare маскирует реальный хостинг — гео по IP ненадёжно, отметь как
«требует ручной проверки договора с хостером»).

## Выход детектора

Структурированная сводка для чеклиста:

```
Тип сайта: <лендинг | интернет-магазин | сайт услуг>
Формы сбора ПДн: <да/нет, какие поля>
Сторонние сервисы: <список доменов + классификация>
Политика ПДн: <есть/нет, где ссылки>
Cookie-баннер: <есть/нет, тип>
Реквизиты: <есть/нет>
Оферта: <есть/нет>
Хостинг (гео IP): <страна, либо «за CDN, проверить договор»>
```

Эту сводку передавай в чеклист ветки — каждый пункт станет строкой отчёта.
