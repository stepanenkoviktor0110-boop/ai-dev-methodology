# Отчёт аудита сайта — форма

Заполняется по результатам детектора + чеклиста ветки. Сохраняй как
`audit-<домен>-<YYYY-MM-DD>.md` в рабочей папке клиента.

---

```markdown
# Аудит сайта на соответствие законодательству

- **Сайт:** {{SITE_URL}}
- **Дата:** {{DATE}}
- **Юрисдикция:** {{ru | eu | both}}
- **Тип сайта:** {{лендинг | интернет-магазин | сайт услуг}}

> ⚠️ Черновик под проверку юристом. Не юридическое заключение.

## Вердикт

{{1–2 строки: соответствует / есть blocker'ы / минорные замечания}}
Blocker'ов: {{N}} · Major: {{N}} · Minor: {{N}}

## Таблица соответствия

| # | Требование | Статус | Severity | Норма | Что нашли |
|---|------------|--------|----------|-------|-----------|
| 1 | {{требование}} | PASS / FAIL / N/A | blocker / major / minor | {{закон, ред.}} | {{факт из детектора}} |

## План работ

Приоритет по severity: сначала все blocker, потом major, потом minor.

### Blocker (штраф/блокировка — сделать первым)
- [ ] {{работа}} → {{какой документ/действие}} → {{оценка}}

### Major
- [ ] {{работа}}

### Minor
- [ ] {{работа}}

## Документы к сборке

Перечень недостающих документов → собрать через `<branch>/templates/`:
- [ ] {{документ}}
```

---

## Правила заполнения

- **Статус:** `PASS` — требование выполнено; `FAIL` — нарушено; `N/A` — не
  применимо к этому типу сайта (например, оферта для лендинга без продаж).
- **Severity** строго по последствию (см. родительский `SKILL.md`).
- **Норма** — конкретная статья + дата редакции. Нет точной нормы — не выдумывай,
  пиши «требует уточнения у юриста».
- **Что нашли** — факт из детектора (домен скрипта, отсутствие ссылки), не
  оценочное суждение.
- План работ — только из строк со статусом `FAIL`.
