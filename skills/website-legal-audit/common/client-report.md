# Подскилл: отчёт для заказчика (нетехнический)

Собирает короткий отчёт для владельца бизнеса по результатам аудита. Простым
языком, без терминов. Это НЕ технический отчёт (`report-template.md`) — тот для
исполнителя. Этот — чтобы заказчик понял: что проверили, что не так, чем грозит,
что делать.

Вызывается последним шагом, когда технический отчёт уже заполнен.

## Принципы (как у скилла `client-report` + инфостиль `pishi`)

- **Простой язык.** Никаких `erid`, `CDN`, `DOM`, `severity`, `трансграничная
  передача` без расшифровки. Пишешь так, будто объясняешь занятому собственнику.
- **Риск — в последствиях, а не в номерах статей.** Не «нарушение ч. 5 ст. 18»,
  а «данные клиентов хранятся за границей — за это штрафуют».
- **Закон называй просто, номер — в скобках.** «закон о персональных данных
  (152-ФЗ)», «закон о рекламе (38-ФЗ)», «закон о защите прав потребителей».
- **Без воды и оценок.** Каждый пункт — факт + чем грозит + что делать.
- **Штрафы — только если сумма надёжна.** Сомневаешься в актуальности суммы —
  пиши «предусмотрен штраф» без цифры. Не пугай выдуманными цифрами.
- **Коротко.** Цель — 1 экран. Детали и нормы — в техническом отчёте, на него
  ссылаешься одной строкой.

## Как собирать

1. Возьми заполненный `report-template.md` (технический).
2. Каждую строку со статусом `FAIL` переведи на человеческий: проблема →
   последствие → что делать. `PASS` сверни в общий список «что в порядке».
   `N/A` не показывай.
3. Сгруппируй по приоритету: «Срочно» (blocker) → «Стоит исправить» (major) →
   «Рекомендации» (minor). Слова `blocker/major/minor` в текст НЕ выноси —
   только заголовки-светофор.
4. Заполни шаблон ниже. Сохрани как
   `client-legal-report-<домен>-<YYYY-MM-DD>.md`.

## Шаблон

```markdown
# Проверка сайта на соответствие закону

**Сайт:** {{SITE_URL}}
**Дата проверки:** {{DATE}}

## Коротко

{{1–2 предложения: в целом всё хорошо / есть что исправить / есть срочные
вещи, за которые штрафуют}}

## Что в порядке

- {{простыми словами, что уже соответствует требованиям}}

## 🔴 Срочно — за это штрафуют

> {{Если таких пунктов нет — убери раздел.}}

**{{Проблема простыми словами}}**
Чем грозит: {{последствие — штраф/блокировка, сумма только если надёжна}}.
Закон: {{название закона (номер)}}.
Что сделать: {{конкретное действие}}.

## 🟡 Стоит исправить

**{{Проблема}}**
Чем грозит: {{последствие}}.
Что сделать: {{действие}}.

## 🟢 Рекомендации

- {{необязательное улучшение}}

## Что мы подготовим

{{Список документов, которые соберём из шаблонов: политика, согласие и т.д. —
простыми названиями.}}

---
Это краткий обзор для ознакомления, не юридическое заключение. Перед публикацией
документы стоит показать юристу. Технические детали и ссылки на конкретные статьи
— в полном отчёте.
```

## Правила перевода «технический → человеческий»

| В техническом отчёте | В отчёте заказчику |
|----------------------|--------------------|
| Нет уведомления РКН (ст. 22) | «Вы не зарегистрированы в Роскомнадзоре как тот, кто собирает данные клиентов — это обязательно, за отсутствие штрафуют» |
| Google Analytics → трансграничная передача | «На сайте стоит зарубежная аналитика — данные посетителей уходят за границу, так нельзя без отдельного разрешения» |
| Согласие не отдельным документом | «Галочка согласия оформлена по-старому — с осени 2025 нужно отдельное согласие» |
| Хостинг за рубежом / локализация | «Данные клиентов хранятся на заграничном сервере — по закону должны храниться в России» |
| Нет реквизитов продавца | «На сайте нет полных данных о продавце (название, ОГРН, ИНН) — для магазина это обязательно» |
| Реклама без erid | «Ваша реклама не промаркирована — за это штрафуют» |
