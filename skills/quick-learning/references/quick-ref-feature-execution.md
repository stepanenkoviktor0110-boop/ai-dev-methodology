# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде перед объявлением "готово" — для cron: проверь лог через 5 мин после первого срабатывания (Seen: 3)
2. Субагент не завершает задачу → lead выполняет напрямую через Write/Edit, не ретраит субагент (Seen: 2)
3. Спорные решения ДО генерации: перед артефактом >200 строк — выписать решения с неоднозначностью, утвердить, только потом генерировать (Seen: 2)
4. Off-by-one в позиционном форматировании — подставить конкретные числа и верифицировать вручную до записи (Seen: 2)
5. Новый sentinel/marker в промте — описать обработку во ВСЕХ секциях и таблицах где маркер может появиться (Seen: 2)
6. False-positive risk в тесте (тест зелёный, покрытие иллюзорно) → создать ad-hoc fix task немедленно, не откладывать в deferred (Seen: 2)
7. Флаг-файл run-once — привязывать путь к стабильному anchor (db_path.parent, Path(__file__).parent), не к CWD (Seen: 2)
8. Production данные не соответствуют поведению кода → сверить timestamp задеплоенного файла с временем запуска (Seen: 2)
9. Изменение одного элемента из sibling-группы (UI-компонент, DB-запрос, route-guard) → явно проверить и применить к каждому «брату» (Seen: 2)
10. Спавнить ревьюеров ПОСЛЕ завершения тиммейта, передав diff в промт — не получить ревьюеров завершившихся до отправки diff (Seen: 1)
11. Тест требует импорта константы из Next.js page/route-файла → вынести константу в utility-файл, импортировать в page и в тест — не добавлять export в page-файл (Next.js запрещает произвольные named exports в page/route) (Seen: 1)
