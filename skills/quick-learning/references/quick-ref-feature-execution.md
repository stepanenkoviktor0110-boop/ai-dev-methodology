# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде: после деплоя curl/лог/grep уникального маркера из нового коммита — «готово» только по факту (Seen: 4)
2. Любое изменение — чини класс, а не инстанс: примени к каждому sibling, grep по structurally-similar местам; отчёт ревьюера — пример приёмки, а не спецификация (Seen: 2)
3. Батч fork-решений: прогони каждое через правило полномочий, реши своё, эскалируй продуктово-видимое; молчание ≠ согласие (Seen: 2)
4. Верификация по случаям через долгоживущий рантайм: свежий инстанс на случай, каждый случай сам ставит свою предпосылку (Seen: 2)
5. Async-агент: назови ожидаемое время до старта, мониторь; перед kill прочитай реальный прогресс, а не догадку о зависании (Seen: 2)
6. Ноль в лимите «как часто / сколько» означает «без ограничения»; ограничивает только положительное значение (Seen: 1)
7. Шаг батча удаляет и пересоздаёт → сохраняй вывод удаляющего шага, считай это двумя состояниями, а не одним действием (Seen: 1)
8. Решение стейкхолдера связывает несколько обязательств → разбей дословно до старта и отчитывайся по каждому обязательству (Seen: 1)
9. Делегат сказал «done», но запустил свою фоновую работу → забери результат у источника, не считай завершение подтверждённым (Seen: 1)
10. Мерж/деплой в mainline → читай живой HEAD/реальный symlink, гейти по descent от истинного состояния, не по nominal ref (Seen: 1)
