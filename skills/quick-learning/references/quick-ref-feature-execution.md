# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде после деплоя (curl/лог/grep уникального маркера из нового коммита) — не объявлять "готово" без подтверждения (Seen: 4)
2. Спорные решения ДО генерации: артефакт > 200 строк → список решений с вариантами → утверждение → генерация (Seen: 1)
3. Субагент не завершил из-за внешней блокировки (права, permission) — lead делает сам через Write/Edit, не ретраить (Seen: 1)
4. Любое изменение — проверяй радиус поражения: sibling-группы, CORS/CSRF при смене домена, hotfix → audit wave, grep structurally-similar endpoints (Seen: 1)
5. Не подтверждай без проверки реальности: grep в коде до ответа, задача done только после реального эффекта — файл создан ≠ фича работает (Seen: 1)
6. Серверные операции — проверяй preconditions (порт, push state, hung process) до дебага логики (Seen: 1)
7. Воркер заявил "checks pass" после правок синтаксис-чувствительных конструкций — перепроверь сам, не доверяй self-report (Seen: 1)
8. Идентичный сбой ≥2 раз — чини источник (поведение/конфиг), не инстанс; разорви symptom-retry loop одним root-фиксом (Seen: 1)
9. Batch fork-решений на голосование — отфильтруй через правило полномочий: реши свои, эскалируй только зарезервированные (Seen: 1)
10. Несколько актёров в одном shared workspace — изолируй в копию/ветку и чекпойнти сразу после верификации (Seen: 1)
