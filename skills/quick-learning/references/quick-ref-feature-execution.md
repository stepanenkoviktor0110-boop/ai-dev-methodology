# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде: curl/лог после деплоя, grep уникального маркера из нового коммита — не объявлять "готово" без подтверждения (Seen: 4)
2. Серверные операции — проверяй preconditions: занятость порта, push state, ручное подключение до авто-попыток, права домашней директории при SSH (Seen: 1)
3. Пользовательские инструкции — уточняй scope: "не нужен" → UI или вся функциональность? Task file > prompt для значений (Seen: 1)
4. Любое изменение — проверяй радиус поражения: sibling-группы, CORS/CSRF при смене домена, hotfix → audit wave, grep structurally-similar endpoints (Seen: 1)
5. Не подтверждай без проверки реальности: grep в коде до ответа, задача done только после реального эффекта в системе (Seen: 1)
6. Спорные решения ДО генерации: артефакт > 200 строк → список решений с вариантами → утверждение → генерация (Seen: 1)
7. Субагент не завершил → lead выполняет напрямую: не ретраить при внешней блокировке (права, permission) (Seen: 1)
8. Баг после деплоя → проверить upstream-инфраструктуру сначала: 4xx после деплоя → настройки платформы, не код/DNS (Seen: 1)
9. Внешний агент (Codex) → полный git diff после завершения, не только целевые файлы — поймать непрошеные изменения (Seen: 1)
10. Несколько гипотез → evidence first: прочитать observable evidence ДО объявления диагноза, не hypothesis anchoring (Seen: 1)
