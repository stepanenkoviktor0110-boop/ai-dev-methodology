# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде после деплоя (curl/лог/grep уникального маркера из нового коммита) — не объявлять "готово" без подтверждения (Seen: 4)
2. Воркер заявил "checks pass" после правок синтаксис-чувствительных конструкций — перепроверь сам, не доверяй self-report (Seen: 3)
3. Идентичный сбой ≥2 раз — чини источник (поведение/конфиг), не инстанс; разорви symptom-retry loop одним root-фиксом (Seen: 3)
4. Batch fork-решений на голосование — отфильтруй через правило полномочий: реши свои, эскалируй только зарезервированные (Seen: 3)
5. Субагент не завершил из-за внешней блокировки (права, permission) — lead делает сам через Write/Edit, не ретраить (Seen: 3)
6. Операция падает одинаково при разных surface-вариантах — читай нижележащий механизм и локализуй сбойный слой до перебора вариантов (Seen: 2)
7. Несколько независимо-скоупленных финальных выходов — финализируй каждую единицу с явными границами до любого catch-all шага (Seen: 2)
8. Спорные решения ДО генерации: артефакт > 200 строк → список решений с вариантами → утверждение → генерация (Seen: 2)
9. Несколько актёров в одном shared workspace — изолируй в копию/ветку и чекпойнти сразу после верификации (Seen: 1)
10. Верификация толкнула бы секрет на логируемую поверхность — перенеси проверку туда, где секрет уже живёт, и отдавай только не-секретные результаты (Seen: 1)
