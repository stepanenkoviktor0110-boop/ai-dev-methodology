# Quick Reference — Feature Execution

1. Верифицируй результат в реальной среде: curl/лог после деплоя, grep уникального маркера из нового коммита — не объявлять "готово" без подтверждения (Seen: 4)
2. Любое изменение — проверяй радиус поражения: sibling-группы, CORS/CSRF при смене домена, hotfix → audit wave, grep structurally-similar endpoints (Seen: 1)
3. Не подтверждай без проверки реальности: grep в коде до ответа, задача done только после реального эффекта в системе — файл создан ≠ фича работает (Seen: 1)
4. Спорные решения ДО генерации: артефакт > 200 строк → список решений с вариантами → утверждение → генерация (Seen: 1)
5. Проверка запретов из спека перед коммитом: task-файл содержит "NEVER X" → grep по запрещённому паттерну в изменённых файлах ДО коммита (Seen: 1)
6. Явная директива о режиме — переключай немедленно: "не спрашивай", "делай молча" → не задавать уточняющий вопрос, переключить режим сразу (Seen: 1)
7. Задача зависит от компонента из предыдущей волны — читай живой код: actual source code interface, не spec-текст (Seen: 1)
8. Несколько гипотез → evidence first: прочитать observable evidence ДО объявления диагноза, не hypothesis anchoring bias (Seen: 1)
9. Код закоммичен — деплой сразу: server-side код исправлен и закоммичен → задеплоить как последний шаг сессии (Seen: 1)
10. Массовая операция над файлами — верифицируй до коммита: после bulk-operation → dry-run/check mode перед коммитом (Seen: 1)
