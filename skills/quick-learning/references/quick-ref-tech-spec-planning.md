# Quick Reference — Tech Spec Planning

1. Верифицируй файловые пути через ls/glob и grep call sites до записи — пути из файловой системы, не из памяти или docs (Seen: 4)
2. Ревьюер уверенно заявляет, что факт неверен — прогони самую дешёвую прямую проверку до действия; уверенность ≠ доказательство (Seen: 4)
3. Перед "удалить/заменить X в N файлах" — grep каждый файл; файл без X требует add, не replace (Seen: 3)
4. Перед включением API response shapes в спек — возьми один живой сэмпл (коды, формат, edge cases); один вызов дешевле миража через pipeline (Seen: 3)
5. При переносе задачи/модуля/пайплайна в другую среду — перечисли все неявные зависимости (env, filesystem, network, runtime, auth); existence ≠ portability (Seen: 3)
6. Запуск task-creator агентов — проверь runner (jest/vitest/pytest) и тест-директории, передай явно в каждый бриф (Seen: 3)
7. Decision сужает/откладывает требование user-spec — сначала проверь user-spec AC и обнови его в том же шаге (Seen: 3)
8. Перед записью сигнатур вызовов в hints — проверь фактически установленную версию пакета, чтобы не дать stale API из памяти (Seen: 2)
9. Внешне названные позиционные атрибуты/символы — сверь с реальными позициями в коде до записи в спек (Seen: 2)
10. Quantitative gate считается по более узкому набору, чем оцениваемый юнит — выровняй scope измерения до чтения числа как вердикта (Seen: 2)
