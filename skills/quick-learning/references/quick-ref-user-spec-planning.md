# Quick Reference — User Spec Planning

1. Генерируй все шаги deliverable целиком — серия промптов, roadmap, план сессий, деплой-инструкция выдаются сразу, не частями (Seen: 3)
2. Для distribution-инструкций конечному пользователю — перечислить prerequisites на чистом окружении до выбора метода доставки (Seen: 1)
3. При 3+ последовательно зависимых deliverables — первый активный, остальные как planned-stubs с видимым прогрессом (Seen: 1)
4. Если репо содержит skills/модули из разных доменов — перечислить все домены и получить is_in_scope по каждому до написания спека (Seen: 1)
5. Если в descriptive-блоке user-spec есть требование, не отражённое в AC — следовать только AC, зафиксировать gap решением (Seen: 1)
6. При добавлении нетривиальной фичи в середине интервью — задать scope-impact вопрос до обновления спека (Seen: 1)
7. Если user-spec описывает delete/cleanup в системе со статусами пайплайна — ограничить удаление терминальными статусами, не значениями полей (Seen: 1)
8. При появлении новой роли в середине интервью — сразу строить матрицу role × capabilities и валидировать с пользователем (Seen: 1)
9. Если пользователь описывает несколько взаимосвязанных фич — явно уточнить порядок реализации ДО инициализации первого folder (Seen: 1)
10. При amendments к approved user-spec — фокус-мини-интервью только по изменённым точкам, не перезапускать полный цикл (Seen: 1)
