# Learned Patterns — Code Writing

> Loaded by audit agents and retrospective only. Orchestrator loads only Promoted Patterns (in SKILL.md).

- When wrapping API calls with a generic retry decorator -> explicitly exclude non-retryable exceptions (auth errors, validation failures) to avoid retrying errors that will always recur
- When unit tests use mocks for external processes/APIs -> run at minimum 1 live smoke run before declaring QA passed, to prevent false all-tests-pass when mock diverges from reality
- When using a retry decorator with a rate-limited API -> verify whether failed requests count toward the quota before enabling retry, to avoid burning quota on pointless retries
- When generating config files with enum fields or nested configs -> verify all allowed values from the official schema/docs including nested objects to avoid invalid-but-plausible values
- When writing deploy scripts that create named resources -> clean up by identity (name/ID), not through management tool, to prevent failure from orphaned resources
- When TDD Anchor describes a test for a private class method -> invoke through an object instance, not through direct import, so tests do not fail with ImportError before running real logic
- When calling clear/reset on an external service before writing new data -> explicitly reset ALL state layers (content + formatting + cache) to prevent previous state from surfacing after cleanup
- When CSS-правило не применяется к элементу несмотря на правильное объявление → проверить наличие inline styles или JS-управляемых стилей на целевом элементе — применять стилизацию через тот же механизм, to не тратить fix-раунды на CSS который не может переопределить стиль с более высоким приоритетом
- When connecting an external library adapter to a DB -> verify the expected object type (raw driver vs query builder) in docs BEFORE writing init code, to avoid runtime adapter incompatibility on first query
- When CI/CD выполняет команду с sudo от deploy-пользователя → проверить права и убрать sudo для доступных операций; явно задать host trust для авто-SSH, to избежать permission denied на первом деплое
- When параллельные тесты используют общий seed-ресурс (пользователь, запись) в тестовой БД → использовать уникальные идентификаторы per-test вместо общей константы, to избежать teardown race condition при параллельном выполнении
- When JS state exists only to toggle CSS values by viewport -> replace state+listener with CSS media queries + className to eliminate re-renders and make layout CSS-controlled
- When интеграционные тесты с разделяемым соединением к БД зависают после завершения suite → добавить явное освобождение соединения в глобальный teardown тест-окружения, не полагаться на GC, to не допустить зависание тест-процесса из-за незакрытого соединения
- When E2E тест с асинхронной UI-операцией (upload, submit, save) → заменить фиксированную задержку (sleep/timeout) на assertion конкретного состояния UI-элемента, to избежать flaky test и false-positive из-за race с таймером
- When implementing an HTTP server with API key auth -> include timing-safe comparison and explicit body size limit in the initial implementation, to avoid a predictable security review round
- When a helper function accepts a value from an external source (API response, env var, user input) -> manually check edge cases (null, undefined, empty string, 0) before first review
- When task has numeric thresholds in code -> extract magic numbers to named constants before first review, to avoid a predictable hardcoded-value review finding
- When a library config option is silently ignored in a new major version -> check option behavior in config-file vs CLI through changelog/issues for the current version BEFORE writing config
- When an integration test checks duplicate/error flow in an auth library -> verify through DB side effect, not HTTP status, to avoid false-negative when library returns 200 with a resend flow
- When E2E global-setup требует предсозданного пользователя с верифицированным статусом → создать пользователя напрямую в БД вместо sign-up flow — снять зависимость seed-фазы от работающего сервера, to гарантировать стабильность setup независимо от состояния сервера
- When adding a new parameter to an existing API request -> check nullable response fields with the new parameter on real data, to prevent TypeError in production
- When передача файла через SSH heredoc/SCP обрывает соединение → передавать через stdin pipe, to не менять auth/порт
- When a bash command passes $(find ... | cut ...) as a path to a flag accepting a file path -> extract the substitution to a named variable in a separate quoted command, to avoid silent false results when paths contain spaces
- When route возвращает 404 без серверных ошибок → перед диагностикой маршрутизации проверить базовый URL конфигурации (лишний path prefix) и compiled output на silent async init failure, to не тратить итерации на маршрутизацию когда источник в конфиге или инициализации
- When dev-сервер возвращает ошибку про отсутствующий модуль при неизменных зависимостях → очистить кеш сборки и перезапустить сервер до диагностики зависимостей, to не тратить итерации на зависимости когда источник — устаревший кеш сборки
- When backlog task adds a guard to a file modified in earlier waves → read the file first to check whether the guard already exists, to avoid duplicating byproduct work
- When исправляется структурное ограничение, нарушённое в нескольких местах артефакта → после исправления первого нарушения — просканировать ВЕСЬ артефакт на остальные вхождения, to не пропустить повторяющиеся нарушения из-за first-fix completion bias
- When gatekeeper rejects all framework-spawned instances despite disguise attempts → connect to already-running unmanaged instance via debug interface instead of spawning new controlled one, to avoid spawn-for-capability bias and work around gatekeeper restrictions
- When удаление элемента, оценённого как самодостаточный → проверить дефолтное состояние всего, чем удаляемый элемент управлял, to не оставить controlled state в непредвиденном дефолте после удаления контроллера
- When система обращается к ресурсу по нескольким различным путям (внешний и внутренний) → перечислить все пути доступа к ресурсу и проверить каждый независимо, to не считать ресурс рабочим на основании одного пути когда остальные пути могут быть сломаны
- When императивный запрос нацелен на элемент в условно рендерящейся части системы → проверить что целевой элемент присутствует безусловно, или перенести идентификатор на безусловный предок, to не получать runtime-ошибку из-за отсутствия элемента объявленного в исходнике но не присутствующего в runtime
- When correction received for incorrect interface usage → verify correct form against authoritative source before committing fix, to avoid fix-that-doesn't-fix and eliminate a double validation round
- When добавление обработки ошибок в переиспользуемый компонент → различать transient (пропустить наверх) и permanent (пометить failed) — не глотать оба через generic Exception, to не скрывать временные сбои под постоянным failed-статусом и не ретраить неисправимые ошибки. Обратный случай: when function wraps external call и catch list перечисляет конкретные exception types для одной семантики ("недоступен") → использовать catch Exception; перечислять типы только когда разные типы требуют разных путей обработки, to предотвратить silent propagation из-за неполного списка исключений.
- When writing idempotency guard for event handler updating multiple fields → base guard on primary state indicator only, not compound check with secondary fields, to avoid bypass gaps when secondary fields are absent
- When test substitutes entire class to mock one instance method; class has co-located pure/static function returning typed result → restore co-located function: mock.pure_fn.side_effect = real_fn, or narrow substitution to target method only, to avoid container-level patch silently replacing co-located functions and turning typed returns into truthy mocks
- When деплой через SSH делает systemctl restart в том же сеансе → проверять статус сервиса отдельным SSH-соединением после паузы, to не считать exit 255 после restart сбоем и не запускать повторный деплой
- When написание теста для шага N многоступенчатого пайплайна, когда входные данные могут не пройти предшествующий шаг → перед написанием теста шага N составить список всех предшествующих фильтров и убедиться что тестовые данные их проходят, to не допустить что тест всегда даёт 0/пусто из-за upstream-фильтрации, маскируя реальную логику
- When в систему добавляется новый HTTP-клиент, когда уже существуют сетевые обходные пути для других клиентов → при создании нового внешнего клиента явно проверить: есть ли proxy/tunnel/workaround в системе → применить к новому клиенту сразу, to не допустить что новый клиент использует прямое соединение в сети с ограничениями, уже обойдёнными для других
- When preparing commit when recently-edited files have unstaged changes and auto-fixing hooks are active → verify git diff --name-only is empty before committing; re-stage all modified files if not, to avoid auto-fix hooks stashing unstaged changes then rolling back on stash conflict, silently undoing all fixes
- When writing test that triggers middleware behavior; event sent in state with no matching handler → verify framework's middleware dispatch model before writing test state: inner/wrapped middleware fires only on handler dispatch, not on all events, to avoid middleware being bypassed silently when no handler matches — test never exercises the logic under test
- When spec prescribes specific test tool for async/stateful component → verify tool-component compatibility; assert observable state (scheduled times, stored values) if incompatible, to avoid prescribed-mechanism trust: using spec's tool name without checking if it works with the target component
- When integration test in wave N references function not yet implemented in future wave → embed minimal local stub matching documented contract; add import-swap comment for when the function ships, to avoid cross-wave forward reference: importing from a not-yet-existing wave boundary as if present
- When implementing a module with exported output artifacts (text constants, side-effect functions) → trace call path from entry point to each artifact before marking done, to avoid definition-as-invocation assumption: treating constant defined and exported as equivalent to used at runtime
- When narrowing a union type that includes inaccessible or test-double variants before method call → check for the unwanted variant (not isinstance(x, Excluded)) rather than asserting the wanted type, to avoid positive type check excluding subtypes: assumes isinstance(x, Target) covers all usable objects
- When relying on a tool for a correctness property (ordering, determinism, idempotency) → verify the tool's documented contract guarantees that property before depending on it, to avoid tool-trust assumption where "works in practice" is taken as "guaranteed by the tool"
- When fixing logic covered by an existing test → check whether the test asserts current (buggy) output and update it to assert intended output, to prevent CI blocking a valid bug fix because the test was a snapshot of the bug
- When using a tool's auto-detection feature to choose a destination/target → compute the explicit destination independently and pass it directly, to avoid silent-fallback assumption where detection failure picks a destructive default
- When a tool's text-mode I/O may transparently transform content (newlines, encoding) → use byte-mode or disable transformations explicitly when byte-equivalence matters, to avoid platform-specific silent translation breaking downstream parsers
- When adding a new external call to an existing module that has test mocks → scan all tests that mock that module's dependencies and update doubles to include the new call before marking done, to avoid partial mutation bias where production gains a call that mocks don't model
- When wrapping an async callable through a generic adapter before passing to a dispatch system → verify the wrapper preserves runtime traits the dispatcher inspects (async nature, signature, attributes), to avoid wrapper-strips-trait assumption
- When writing a test that claims to verify two operations run concurrently → assert ordering or interleaving (second started before first finished), not merely that both ran, to avoid existence-proof masquerading as ordering guarantee
- When implementing a fallback path for a missing or unregistered optional dependency → emit a named warning-level log event before taking the fallback, to avoid graceful degradation masking wiring failure
- When building a test helper for a behavior not yet implemented in production → defer the helper or add an explicit "not yet assertable" marker, to avoid infrastructure-readiness assumption that helper presence implies behavior exists
- When a function's success path performs both a state mutation and an audit/log write, with branches that throw before the audit-write → in every error branch emit the same audit record (with failure marker) before propagating, to avoid audit-write skip on error paths leaving mutations unrecorded
- When "no references found" used as precondition for irreversible action → before trusting absence, deliberately search for a case known to match and confirm it's found, to avoid false safety signal from search tool that silently skipped files
- When subprocess must outlive current agent turn → spawn at OS level (detached, output redirected to file) not as agent-managed background task, to keep process alive when agent turn ends
- When generating shell/CLI commands into a downstream artifact for later execution → check the host's actual shell at decision time and emit each command in that shell's native syntax; do not propagate upstream-spec dialect verbatim, to avoid host-shell default bias (defaulting to dominant-platform dialect like Unix grep/find/rm -rf/& without re-reading project context that has declared a different shell)
- When task has a dedicated workflow that owns required tooling → invoke the workflow instead of reproducing its steps from memory, to not silently skip the integrated tooling the workflow would fire (triad #378)
- When need to observe/override a call into a third-party or native object whose method resists interception (read-only, compiled, frozen) → route the call through a thin wrapper you own and intercept that, to avoid universal-patchability assumption: assuming every callable can be monkeypatched in place like an ordinary attribute (triad #382)
- When a verification command whose exit status decides pass/fail is piped into a trailing filter/formatter/pager → read the meaningful command's own exit status (run it unpiped, redirect to file, or inspect the specific stage), to avoid pipe-masked failure status: trusting a pipeline's green exit code when that code comes from the always-succeeding trailing filter, hiding the verifier's real failure (triad #393)
- When a script is delivered to an interpreter through that interpreter's own stdin (pipe / heredoc / `interp -s < file`) → isolate every inner command that itself reads stdin by redirecting its input from an empty source, to avoid piped-stdin script self-consumption: assuming the no-interaction/no-TTY flag stops an inner command from swallowing the rest of the script (triad #399)
- When an exact-string edit fails on text that visually matches the target → suspect invisible/look-alike unicode (nbsp, fancy arrows/dashes, zero-width) from the generator; anchor on the smallest unique ASCII-only substring or normalize first, to avoid visual-match != byte-match: re-sending the same full line burns rounds without resolving the byte mismatch (triad #417)
